# 工作原理与界面设计

## 工作原理

```
音频文件 ──► 解码 (Core Audio / miniaudio) ──► 44.1 kHz 立体声
   │
   ├─► MDX-Net Voc_FT：STFT(7680/1024) → [1,4,3072,128] → ONNX → iSTFT，
   │   分块 + Hann 重叠相加（UVR demix 的移植）                  ──► 人声
   │
   ├─► VR 6_HP-Karaoke：多频带 STFT + 重采样拼接 → 全曲最大值归一化 → 512 帧窗口
   │   （与 UVR 整曲处理同一网格，每个窗口推理一次）→ ONNX 掩码 → aggressiveness →
   │   (1-mask)·X → 分频带 iSTFT 合成                              ──► 主唱
   │                                                            伴奏 = 原曲 − 主唱
   ├─► SwiftF0 音高模型（16 kHz，16 ms 一帧；错开 4 ms 跑 4 遍）→ 插到 5.8 ms 的帧上
   │   + 电平门限、八度纠错、中值滤波 ──► 音高曲线（模型用不了时用 YIN，22.05 kHz、1024 点窗）
   │   同一帧上记录 RMS 电平，供句尾收束和音高门限使用
   │
   └─► 逐句对齐：从单声道人声按 LRC 截出每句，前后各多取 0.4 秒
       → HuBERTFA 音素和边界分数 → 按词典读音强制解码（允许 SP）
       → 把音素时间合并到歌词字词，按音高和电平确定句尾并提取稳定音符
                                                              ──► 逐字音高图（本地保存）

练习：全双工音频引擎（播放伴奏 + 采集麦克风，同一回调）给每个采集块打上
“当时正在播放的歌曲帧号”，减去系统延迟后 → 实时 YIN（2048 点窗、10 ms 步长）
→ 与该时刻的参考音符（导入时用音高模型测好、存在本地）比较（可忽略八度）→ 每个字的覆盖率、音分偏差中位数、
稳定度、起唱时间 → 评分与问题标签。
```

关键实现细节：

- **分离结果与 UVR 一致**：`tools/reference/make_separation_fixtures.py` 直接运行 UVR 自己的
  `spec_utils.py` 和 MDX `demix` 代码，测试用相同的确定性“假模型”比对 Dart 实现，
  两种 karaoke 频带配置、两个 stem 的误差都在 2e-4 以内；VR 分段处理与整曲处理的差别在 1e-5 以内
  （测试用依赖整个窗口上下文的假模型，段长从 0.1 秒到 15 秒都验证过）。
  真实两个模型也按 App 的参数对照：14 秒合成混音上，MDX 信号/差值比 120.0 dB，
  VR 主唱 141.3 dB、被移除部分 118.2 dB，详见[验证记录](inference-memory.md)。
- **速度与内存**：MDX 单块滚动累加，模型推理当前块时同时计算下一块的 STFT 和上一块的逆变换。
  VR 不能一次放下整首歌的频谱，所以约 15 秒一段计算，但窗口放在 UVR 整曲处理的同一网格上：
  每个窗口只推理一次，段边界只多算几帧上下文，结果与整曲处理在浮点误差内相同，不需要交叉淡化。
  VR 期间释放混音，结束后重新解码并复用为伴奏缓冲。两个模型顺序加载、关闭，CPU arena 关闭
  （Apple 插件为此带有本地补丁）。桌面独立推理峰值 MDX 约 508 MB、VR 约 1072 MB（512 窗口）。
  导入开始时读取 iOS 报告的剩余内存（`os_proc_available_memory`），不够 512 窗口用时自动改用 320
  （约 835 MB，但推理次数是 4 倍），小内存的旧 iPhone 也能完成。真机峰值仍须用 release + Instruments 验收。
- **STFT / 重采样**：与 `torch.stft`、`librosa.stft`、`scipy.signal.resample_poly` 的数值一致（有测试）。
  采样率不是 44.1 kHz 的文件（比如 48 kHz 的 wav）先用带抗混叠滤波的多相重采样转换，
  高频不衰减，也不会多出原来没有的频率。
- **原唱的音高用音高模型 SwiftF0 测**（Lars Nieradzik，MIT）：1.4 万个参数的卷积网络，从频谱读出每 16 ms 一帧的
  音高和“这一帧有人声、音高可信”的置信度（≥ 0.5 算有声），只在 60–1400 Hz 里找。它是在语音和乐器上训练的，
  训练时混进了噪声、别的音乐和房间混响，所以分得清人声和背景，不像 YIN 只看波形周期性是否超过阈值。
  在 MIR-1K（19 位歌手的中文卡拉 OK 演唱，人工标注音高，不在它的训练数据里）上，按导入的实际做法
  （人声和伴奏混成原曲，用 App 的人声分离分出人声，再测分离出的人声）整体准确率 92.4%（YIN 90.2%），
  干声上 95.5%（YIN 93.8%）。详见[验证记录](pitch-model.md)。
  - 测的是分离出的人声（或用户导入的纯人声文件），不是原曲；测一次，存在本地，每次练习直接用。
  - 模型输出的帧间隔是 16 ms，比逐字对齐用的 5.8 ms 粗，所以把人声错开 0、4、8、12 ms 各跑一遍，
    每个 5.8 ms 帧取前后两个模型帧之间的置信度和音高。电平和频谱变化仍按原来的帧计算，
    门限、八度纠错和中值滤波也照旧，对齐看到的是同样格式的音高曲线。人声先归一化到峰值 −6 dBFS（模型本身不归一化音量）。
  - 模型加载或运行出错时，这首歌改用 YIN 测完（歌曲信息里记着用的是哪个）。
- **你唱的音高用 YIN 实时测**：差分函数用 FFT 互相关计算（O(N log N)），带抛物线插值。
  模型要听到一帧之后约 80 ms 的声音才测得准，实时显示会比 YIN 晚约 70 ms，所以练习和自由练习仍用 YIN。
  两者在同一段人声上测出的音高中位数只差约 1 音分，远小于评分的容差。
- **逐句对齐**使用 HuBERTFA v0.0.7 的 v5 ONNX 导出。模型输入是 44.1 kHz 单声道人声，
  内部重采样到 16 kHz，输出每 10 ms 的音素和边界分数。每首歌共用一个 CPU session。中文先按词组生成拼音，
  每个字的音素合成一个字区间。英文和日文用发布包里的词典。校正页设置的拼音优先于自动生成的读音。
- **句尾**以模型给出的最后一个字为起点，沿已保存的音高曲线和 RMS 电平查找有声尾部。
  持续约 80 ms 的无音高或低电平会结束延音，邻句重叠则以模型预测的下一句字头为界。
  极长的 LRC 间隔最多送入模型 20 秒，已连上的长音仍可沿音高轨迹延长。
  音符来自导入时测得的音高曲线，可由 SwiftF0 或 YIN 提供。
- **同步**：伴奏播放和麦克风采集在同一个音频回调里完成，所以每个采集样本都能精确对应到歌曲位置，
  单句循环跳回时也不会错位。

  83% → 86%、60% → 67%。偏差超过 0.25 秒或落到相邻字上的少了 20–34%，男声偏晚的少了一半，

### 模型下载

主线路是 `hf-mirror.com`（Hugging Face 镜像上 `Blane187/all_public_uvr_models` 固定提交的同名文件，
已核对与官方文件的大小和 SHA-256 相同）。连不上、被转到 Hugging Face 主站（301/308 重定向，
在中国大陆以外会这样）、服务器报错、下载中断、半分钟内一直慢于 48 KB/秒，或者文件校验不对时，
App 自动改用备用线路：UVR 官方模型库（`github.com/TRvlvr/model_repo` 的 release），
已下载的部分接着续传。下一个分离模型先用刚才成功的线路。

HuBERTFA 使用上游的 GitHub Release 压缩包。下载后校验 SHA-256，流式解压权重和词典，
安装完成后删除压缩包。

## 界面设计

配色取自中国画的矿物颜料，每种颜色只表达一个意思：墨（文字、原唱旋律、主要按钮）、
宣纸（底色，像乐谱纸）、石绿（唱准 / 好）、朱砂（唱高了 / 差）、石青（唱低了）、
藤黄（接近 / 不稳）。练习时你的声音轨迹按音分偏差在 石青 → 石绿 → 朱砂 之间连续变色，
一眼就能看出是高了还是低了，而不只是对错。逐字音高图像乐谱一样排版：每个字的音是一笔墨线，
字写在线上方；评分页把需要加强的字做成大字卡片。支持深色模式。

`test/design_preview_test.dart` 可以用一首真实歌曲渲染所有页面的截图（浅色 / 深色），
方便检查设计：

```bash
DESIGN_SONG_DIR=<含 reference.json、pitch.bin、vocal.wav 的目录> DESIGN_LYRICS=<歌词.lrc> \
YINTRACE_AUDIO_LIB=$PWD/build/host/libyintrace_audio.so SCREENSHOT_DIR=build/design flutter test test/design_preview_test.dart
```

`test/real_vocal_test.dart` 对任意纯人声 + 歌词运行音高分析和旧版启发式对齐，供对照，并输出每个字的时间
（`REAL_VOCAL=人声.wav REAL_LYRICS=歌词.lrc REAL_OUT=输出目录`）。

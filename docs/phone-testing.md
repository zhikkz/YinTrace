# 只用 iPhone 测试

不需要 Mac，也不需要专门的测试工具：装上测试版 App，在手机上跑一遍“性能测试”，
再用自己的歌试一遍导入和练习，把报告和发现的问题发给开发者。

## 安装包

CI 每次构建都会产出测试版安装包 `YinTrace-test-unsigned.ipa`（GitHub 上 CI 运行页面的
Artifacts 里的 `YinTrace-test-ipa`，下载后是一个 zip，在“文件”App 里点一下就能解压出 .ipa）。
它和正式版是同一份代码，只是打开了 `--dart-define=YINTRACE_TEST_BUILD=true`：设置里多了
“测试版”一组（性能测试、只用备用线路重新下载模型），下载模型时还会显示用的是哪条线路。
正式版没有这些，下载线路在后台自动切换，用户不用管。

安装包**没有签名**，需要你用自己的 Apple ID 签名后安装（免费 Apple ID 就行，用你平时用的
签名工具）。App 没有用到任何需要付费开发者账号的权限，免费账号可以签。注意：

- 需要 iOS 16 或更新的系统。
- 免费 Apple ID 签的 App **7 天后打不开**，要用签名工具重新签名或刷新。只要包名不变，
  覆盖安装会保留曲库和已下载的模型。
- 免费账号同时最多装 3 个自签的 App，每 7 天最多注册 10 个包名。签名工具改了包名
  （本来是 `io.github.zhikkz.yintrace`）也没关系。
- iOS 16 以后要打开**开发者模式**：设置 → 隐私与安全性 → 开发者模式（第一次装自签 App 后
  才会出现），打开后手机会重启，重启后再确认一次。
- 第一次打开如果提示“未受信任的开发者”：设置 → 通用 → VPN与设备管理 → 点你的 Apple ID → 信任。
- 第一次练习时会请求麦克风权限，请允许。

## 一、性能测试（最重要，大约 5 到 10 分钟）

1. 连上 Wi‑Fi，接上电源。
2. 打开 YinTrace，点曲库右上角的设置 → 测试版 → **性能测试**。
3. 合成歌曲长度选 **4 分钟**，点“开始测试”。第一次会先弹出下载模型（194 MB），下载完测试自动开始。
4. 测试期间让 YinTrace 一直在前台，不要锁屏或切到别的 App（屏幕会保持常亮）。
   手机会发热，这是正常的。
5. 被打断也没关系（来电、App 被系统关掉）：重新打开性能测试页，点“接着测没做完的项目”。
   如果某一项让 App 被系统关掉，续测时会自动跳过它，并在报告里写明。
6. 测完后点 **复制报告**，粘贴到聊天里发给开发者。

测试只用 App 自己合成的歌，不读取你的曲库，不上传任何东西；测试用的文件测完就删除。
报告里只有测速结果、手机型号和系统版本。

报告回答两个问题：

- 导入一首 4 分钟的歌要等多久，各阶段花了多少时间，“预计还需”准不准，内存用了多少；
- 人声分离用 GPU（Core ML）和用 CPU 各有多快、结果是否一致。
  第一次测出人声模型在 GPU 上快约 3 倍且结果一致，App 已经默认用 GPU 做人声分离。

## 测试备用下载线路

模型默认从 hf-mirror.com 下载；连不上、被转到 Hugging Face 主站（301/308 重定向）、报错、中断、太慢
或文件校验不对时，自动改用备用线路：GitHub 上 UVR 的官方模型库（同样的原版文件，下载后核对 SHA-256），
不需要用户做任何选择。测试版的下载窗口会显示“备用线路 github.com”，正式版不显示。两条线路都失败才会报错；
测试版还会在红字下面写明两边各自的原因。

如果你那里 hf-mirror.com 本来就能下载，可以专门试一下备用线路：设置 → 测试版 → **只用备用线路重新下载模型**
（会删掉已下载的模型再下载 194 MB，已经导入的歌不受影响）。下载完成后模型能正常导入歌曲，就说明备用线路可用；
失败的话把下载窗口里的红字截图发给开发者。

## 二、用自己的歌试一遍

准备一首歌的音频（mp3、m4a、flac 或 wav，存在“文件”App 里）和这首歌带时间的歌词
（每行写成 `[分:秒.百分秒]歌词`，时间是这一句开始唱的时刻）。音频和歌词只在你的手机上使用，
不要发给开发者。

1. **导入**：曲库 → 导入歌曲 → 选择音频，填歌名，粘贴歌词 → “分离人声，生成音高图”。
   - 进度条和“预计还需”是否一直在动、是否大致准确；记下实际用了多久。
   - 导入途中 App 有没有闪退（闪退多半是内存不够，请记下手机型号和歌曲长度）。
   - 第一次导入完成后，看 设置 → “用 GPU 加速人声分离” 下面的说明：应该是“在这台设备上和 CPU 对比过，结果一致”。
     如果写着“已自动关闭”，把那句话发给开发者。
2. **练习**：戴上耳机（有线最好），点开歌 → 整首练习，播放并跟着唱。
   - 点播放后应该一直放下去，不会闪一下又回到暂停（上一版的问题）。如果还是会自己停：
     点右上角的“练习设置”，拉到最下面，把“测试版：最近的音频事件”那一段截图发给开发者。
   - 你的音高线颜色：绿色是唱准了，红色偏高，蓝色偏低，黄色接近。
   - 音高线总比原唱靠右（慢半拍），就到设置里把“延迟补偿”调大；蓝牙耳机通常要 +150 到 +250 ms。
   - 暂停时连着点几次“下一句”：每点一次往后跳一句，歌词跟着换成那一句（上一版会卡在同一句）。
   - 唱几句后不看评分，直接返回歌曲页：唱过的句子旁边的分数应该已经更新。
3. **听原唱**：练习时点歌词下面的“听这句原唱”。应该放这一句（原唱人声很清楚），上方显示“正在听原唱”；
   放完自动回到这一句开头、暂停，点播放就能跟着唱。评分页每一句旁边的人像按钮也一样。
4. **回听**：唱完一遍会出现评分页（中途看可以点右上角的“查看评分”），点“回听这一遍”，
   或某一句旁边的耳机图标。你的声音应该和伴奏对齐，原唱静音。
5. **制作成品**：评分页点“制作成品”，等“正在保存录音”结束，进入成品页：
   - 点播放试听，边听边拖“人声”“伴奏”“混响”“人声对齐”，声音应该马上跟着变；
   - 点“导出成品”，进度条走完后会弹出系统分享面板，可以“存储到文件”或发给别人；
   - 打开“文件”App → 我的 iPhone → YinTrace，能找到刚导出的 m4a，用别的 App 也能播放；
   - 回到歌曲页，“我的录音”里有这一段，点开可以再导出一次。
6. **校正位置和音高**：歌曲页某一句右边点笔图标。选一个字，点“听原唱”“听目标音”“一起听”对比；
   点“升半音”等按钮后，目标音和音高图马上变，返回歌曲页那一句下面写着“校正过 N 个字”；
   再练这首歌时用的是改过的音高。“恢复自动识别”能退回。
   - 找一个放错位置的字（听原唱时它的开头在前一个字里，或者唱的已经是后一个字）：用“开始时间”下面的
     按钮或长按音高图把它放到原唱唱它的地方，这一句后面的字应跟着回到正确位置，别的句子不变；
     “听原唱”听到的是新的范围。返回歌曲页再进来，位置还在；“恢复自动识别”回到自动对齐的位置。
7. **英文歌、日文歌**：各导入一首（歌词用你自己的，照常 `[分:秒.百分秒]歌词` 一行一句）。
   - 导入页歌词下面应显示“N 句，M 个词（英文）”或“…个字（日文）”；
   - 英文歌词在练习页和歌曲页里单词之间有正常的空格，单词的起点落在它第一个音节上；
   - 日文的小假名（きょ、しゃ）、促音“っ”和长音“ー”不会被拆成单独的字；汉字后面可以加读音
     `心(こころ)`，对齐会更准；日文汉字应该是日文字形。
8. **打断**：练习时锁屏、来电、拔耳机或断开蓝牙，应该立刻暂停，不会突然从扬声器外放；回来点播放能接着唱。
   插上耳机时不应该暂停。
9. **得分趋势**：同一首歌整首唱两遍以上，歌曲页会出现得分趋势；单句循环几次，这一句旁边出现小折线。

## 怎么反馈问题

- 截图：同时按侧边按钮和音量加键。
- 录屏：控制中心里的屏幕录制（没有的话在 设置 → 控制中心 里添加）。
- 写清楚：手机型号、iOS 版本、做了什么、期望什么、实际发生了什么。
- 性能测试的报告直接复制粘贴；不要发送歌曲音频、歌词或导出的成品。

开发者有 Mac 时可以用 [真机测速](device-benchmark.md) 的脚本拿到同样的报告，
内存的精确测量（Instruments）见 [iOS 验收清单](ios-validation.md)。

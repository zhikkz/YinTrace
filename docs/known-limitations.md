# 已知限制

- **逐句对齐**依赖 LRC 时间戳附近的主唱和词典读音。时间戳误差超出 0.4 秒的余量时，
  可以调整 LRC 时间戳。日文汉字可以在 LRC 中注明假名读音。词典外的字词仅用模型的发声和边界分数定位。
- **中文读音**来自歌词文字。比如“头发长了”目前把“长”读成 `chang`，唱的是头发长出来时会读
  `zhang`。“露出”的 `lu chu` 和 `lou chu`、以及“谁”的 `shei` 和 `shui`，还会随原唱的习惯而变。
  听到不同的读音，可以在校正页选中字，点“修改拼音”。
- HuBERTFA 的耗时和峰值内存还有待手机真机实测。
- 原唱音高的有声判定、旋律解码、句尾对齐的先验和引导线的分段参数，是在两首商业歌曲（一男一女，中文）上对照
  RMVPE 和频谱图定的（男声那首还对照了去和声后的版本），没有人工标注，也没有在英文、日文歌上测过；
  两个声部同时唱（主唱叠和声）时，选哪一个声部看哪一个更连贯、模型更听得到，个别短字可能仍会选到和声。
- “重新对齐”时用保存的人声（AAC 压缩过）重测原唱音高，在 iPhone 上要多花几秒；这一步在手机上的耗时还没测过。
- 接入 HuBERTFA 之前的 iPhone 实测（iPhone18,3，iOS 27.0.1，8 GB 内存，测试版的“性能测试”，4 分钟的合成歌曲，两个模型都用 CPU）：
  完整导入 236 秒，约等于歌曲时长（人声分离 95 秒，去和声 135 秒）。同一台 4 核桌面上同一段 259.6 秒的输入，
  完整导入用 273 秒，改动前用 722 秒（[验证记录](inference-memory.md)）。手机上的耗时取决于机型；
  导入页按这台设备的实测速度显示预计剩余时间。
- 人声分离在 Apple 设备上默认用 Core ML（GPU）：在上面那台 iPhone 上每次运行 0.26 秒，CPU 4 线程是 0.76 秒，
  与 CPU 的差值比 109 dB（结果一致），内存和 CPU 差不多。每台设备第一次导入（以及 App 或系统更新后）先用一段和 CPU 对比；
  不一致、出错，或 App 在启动 Core ML 时被系统关闭，都会自动改回 CPU。用 Core ML 的完整导入还要再测一次。
- 去和声模型只用 CPU：在那台 iPhone 上它的每种 Core ML 设置都让 App 被系统关闭。它是导入里最慢的一步，
  所以导入页默认不去和声，和声明显时再打开（上面的 236 秒是打开时的耗时）。
- 内存不足时自动改用的 320 窗口要多跑 4 倍的去和声模型，导入会明显变慢。
- 解码和 VR 输入/输出仍随曲长占内存，尚未做到整条流水线流式处理。
- 分离和去和声的质量取决于 UVR 模型本身；有残留伴奏的段落会被电平门限过滤，可能少测到个别字。
- 练习升降调幅度越大，鼓点和齿音越容易听起来发糊，原唱的音色也会跟着变。iPhone 真机上的处理耗时、内存和听感还没测。
  换过的调存放在系统缓存里，系统清理缓存后，下次切到这个调会再处理一次。
- 练习时外放会让麦克风录到伴奏，请尽量戴耳机；制作成品时，外放录下的伴奏也会混进人声里。
- 延迟校准有合成录音测试，还没在 iPhone 真机上验证。外放、有线耳机和蓝牙耳机都要实测，
  尤其要确认蓝牙耳机跟拍测出来的值，以及普通模式和测量模式的差别。
  补偿按系统报的线路类型记，同类型换了另一副耳机时可以再测一次。
- 练习时的有声判定能挡住电器嗡嗡声、敲击和打字声，你唱过以后也能挡住一部分比你小声很多的电视和说话声；
  但离麦克风近、音量和你差不多的别人的声音（它也是人声）仍会被当成你在唱，你开始唱之前的电视声也一样。
  比上一句小 22 dB 以上的乐句可能丢掉一部分。判定的参数是在合成的房间录音上定的（`test/support/noisy_room.dart`），
  还没有在真实房间里系统地测过。
- 耳返最高 +24 dB，没有啸叫检测：耳机里的声音大量漏回麦克风时会啸叫（限在 −3 dBFS），需要戴好耳机或调低耳返音量。
- 测原唱的音高模型在真机上的导入耗时还没测过（模拟器上性能测试的“测量音高”一步 1.8 秒）。
  测试版设置里可以把原唱音高改回 YIN 测，对比两者画出的音高图。
- 混响是一个简单的房间混响（Schroeder–Moorer 结构），不是专业的人声处理链：没有压缩、均衡和修音。
- 这个仓库里的 iOS 部分在 Linux 环境中开发，C/Objective-C 代码无法在本地编译验证，
  CI 新增了模拟器冒烟，但麦克风授权、音频中断、耳机路由、延迟和长歌曲峰值仍须真机验收。
  练习用的低延迟 RemoteIO 设备（`yt_device_ios.inc`）只在真机上运行（CI 的冒烟测试用空设备），
  它的耳返延迟数值是按缓冲大小算的，还没有在 iPhone 上实测；采样率转换部分（`yt_rate_bridge.h`）有原生测试。
